# 内容整理与验收标准

## 分流

- 产品FAQ：一个完整问题或业务主题一份，保留适用条件、分支和来源。产品介绍与内部报价/操作分库；历史价格标原始日期，不当现行政策。
- 学员心得：概览和重点在上、完整第一人称清洗原文在下。案例、感受和行动不改成机构结论。
- 直播/集训：按完整教学主题或案例拆分；保留问题—回应—修正链，发言角色、时间码和源段落。后续回应可关联但标明非连续，不能伪装成连续对话。
- 空白/TBD：标资料待补，不能生成不存在的答案。资料不全仍可按用户范围上传内部试用稿，状态保持待核。

每份Markdown应有：`## 内容概览`、`## 重点索引`、`## 完整原文`、`## 来源与核对说明`。标题可补充AI整理/清洗版等说明。

源件保留独立originals目录，不直接覆盖。校对只改确定的错字、断句、标点和可核实术语；歧义保留并注待核。AI概览不得增加结果、因果、条件或数量。源日期、整理日期、政策生效日期分开。

删除寒暄、调音、活动促销等噪声需逐段记录排除理由；不能把长案例或难处理细节当噪声丢弃。课件未附、书名错转、人物角色不清时明确说明缺项，不能补造图表或猜测作者。完整是“该主题对应的正文完整”，不是每份重复附上整本源文件。

人员匿名化保持稳定编号和讲者/学员/转述个案角色。抹去无关姓名、联系方式和可识别组合，保留理解案例必需的条件。授权公开与内部入库分开；不将个人观点标成机构已确认。

## 状态与证据

1. prepared：本地整理与来源检查完成，可按授权入内部试用库。
2. uploaded：服务器已接收，有文件ID。
3. indexed：解析完成且下载指纹一致。
4. retrieval_checked：具体细节检索命中正文；平台Summary命中另记。
5. business_review_pending / confirmed：角色、条件、缺项及回答准确性由业务确认，记录确认人和日期。

Agent通过工具最多验证第4层，不能替业务负责人确认第5层。不要伪造审阅人或用脚本退出0代表内容正确。

## 已知平台问题与固定测试

2026-09-20试点已实测：自动Summary把“在节点汇报”写成“仅在节点汇报”，然后被问答引用；长回答可能中途结束；咨询个案可能被误称为学员经历。

因此检索报告分开记录正文和Summary，问答核对以原文为准。提问至少覆盖：

- 原案例具体做法和结果，能否找到原段落？
- “可以/可能/部分”有无变成“必须/仅/全部”？
- 是本人经历、老师转述还是学员假设？
- 缺表、日期未核或书名不清时能否承认不知道？

发现自动摘要或回答错误，保留实际回答和引用片段类型，列入待修；不能为让测试通过而改写原稿。缺资料不使用外部知识冒充原课内容。批次技术成功后仍可交付内部试用，但要明确未通过项目。

## 各类资料的上传规范

目标库由管理员确认实际ID；下表是分类原则，不自动新建库，也不凭库名推断权限。

| 类型 | 入库单元与完整保留内容 | 专项核对与去向 |
|---|---|---|
| SW笔记/方法文章 | 一篇完整文章；过长按独立主题拆，保留定义、推理、例子和适用边界 | 保留系列及篇目编号、前后文关联；进SW笔记对应库，不能把AI延伸写成原作者观点 |
| ACC学员心得 | 一位学员的一篇完整心得；上方概览和重点，下方清洗原文 | 保留第一人称、具体事件、对话、尝试与结果；隐私脱敏后进ACC心得库，感受不升级为通用效果承诺 |
| 产品/课程常见问答 | 一个问题及完整回答，或不可拆开的业务主题 | 保留前提、例外、时间、产品版本；公开介绍与内部报价/操作分库；重复问题核对版本后建立关联，不擅自合并冲突答案 |
| 直播内容 | 一个完整问题链、案例或教学主题 | 保留提问—回应—追问—修正、发言角色、时间码；同场建立主题索引。调音、寒暄等排除须留记录；进直播案例与问答库 |
| 集训/课程教学 | 一节课内一个完整教学主题/练习/案例 | 保留授课顺序、练习指令、学员反馈、老师点评，关联课次和课件页码；不同课程分库，例如事业灯塔与情绪管理分别进入对应教学库 |
| 制度/操作说明/内部手册 | 一项完整流程及其条件、步骤、例外 | 记录责任人、版本、生效时间和废止信息；进内部操作库。未确认版本不能当现行标准 |
| 课件/扫描PDF/图片/音视频 | 先提取文字、OCR或转写，再按上述业务类型整理 | 人工核对关键数字、术语、表格和说话人，保留页码/时间码；纯图片或未转写媒体不直接交给本版MCP上传工具；缺失图片内容明确待补 |

每份稿的“来源与核对说明”应包括：材料编号、资料类型、源文件名、来源定位、原始日期（未知直写未知）、整理日期、版本、适用范围、确认状态、缺项及关联材料。MCP的sources参数同时记录来源SHA256；不要把本机私人绝对路径写进上传正文。

本版通过MCP传输清洗后的Markdown正文，完整原件留本地追溯。小表格完整保留行列及单位；大表按有业务意义的段落拆分，并重复必要的列头。不得用概括替代数值。遇到本表外的材料，先判断信息结构与使用目的，再给出对应整理方案，不机械套为FAQ。
